What does StillHere do?

StillHere saves a local copy of messages displayed in Zalo Web, Messenger or Facebook Messages so you can view them after recall. This is an independent extension, not affiliated with or endorsed by Zalo/VNG or Meta. The current version is free.

Data processed

After you consent and enable capture, the extension reads content already loaded in the Zalo Web conversation interface and visible conversation previews: text, sender name and avatar, message identifiers, conversation identifier/name/type/avatar, timestamps and recall status. The original must be saved before recall.

You may optionally enable avatar and media caching. With Zalo CDN permission, the extension downloads avatars, stickers, images and video referenced by visible messages. For E2EE resources, it may save a decoded blob loaded by Zalo in the interface. Voice messages and other files retain descriptions. Resource addresses are restricted and stored with encrypted metadata. Zalo E2EE keys, passwords and login cookies are not collected.

Messenger and Facebook Messages

Facebook access covers facebook.com, www.facebook.com, web.facebook.com and Messenger. These permissions are requested only when you select Facebook. Already-open tabs are connected after access is granted, without a page reload.

Optional *.fbcdn.net and cdn.fbsbx.com access allows downloading recorded Facebook avatars and resources. Downloads omit cookies and referrers and are limited to 20 MB per file. Facebook redirects are constrained by the extension connection policy. The final URL and download permission are checked again before reading the file. Supported file signatures are checked before encrypted storage. Facebook avatars in the popup are displayed only from local cached copies. The CDN receives the device IP and requested resource URL during downloads.

While capture is enabled, the Facebook reader records rendered text in the open conversation, message and conversation IDs, conversation and sender names, and the time a recall is detected. It runs on messenger.com and www.facebook.com/. Facebook and Zalo have separate menus, with a shared password and storage limits in the Chrome profile. The reader does not access login cookies, passwords, E2EE keys or unrendered internal message data. E2EE content can only be saved after Messenger decrypts and displays it. Messages recalled before capture cannot be recovered.

The Facebook reader records text and resource addresses for rendered images, GIFs, stickers and videos. A file is available after recall only if its copy finished downloading beforehand; poster-only previews are labelled. The extension locks when it detects an account-name change, when you choose to log out, or when you open the profile picker or choose a quick Switch to action in the supported own-account menu, even while capture is paused. Other account-switching flows may not be detected. Accounts in the same Chrome profile share the extension storage and password; do not share the Chrome profile or extension password. The extension is independent and is not affiliated with or endorsed by Meta.

Storage and retention

Saved content and metadata are encrypted with AES-256-GCM in the extension’s IndexedDB. File contents are encrypted with AES-256-GCM in the extension's IndexedDB. The encryption key is derived from your password using PBKDF2-SHA-256 (600,000 iterations). It is held in trusted extension session storage until you fully quit Chrome, and is cleared when the session is locked for security. File size, format and a hash of the resource address support cache management. Temporary conversation detection status is stored in chrome.storage.session.

Resource downloads use HTTPS from *.zadn.vn, *.zdn.vn, *.dlfl.vn, file-stal-*.flchat.vn and sticker paths at api.zalo.me. The CDN receives the requested URL and your IP address. Downloads into the encrypted cache omit credentials and referrers. Video downloads may redirect from dlfl.vn to file-stal-*.flchat.vn. StillHere reads the file only when the final address is a supported Zalo CDN with your granted access. Message and file copies stay on your device; the developer does not receive their content. Avatars may load directly from the CDN before a local copy is available; direct image requests follow Chrome's cookie and network settings. When cached, the popup decrypts and displays the local copy.

The default retention is up to 30 days from first capture, with a 7-day option. Metadata is limited to 1,500 messages or approximately 4 MB. The file cache is limited to 100 MB total and 20 MB per file. Older files are evicted when needed. Files no longer referenced are cleaned up on expiry or archive deletion. Cleanup runs hourly while Chrome is active and the vault is unlocked; expired records are also removed when the archive is opened after unlocking.

On-page viewing and tab connections

The scripting permission and access to Zalo, Facebook and Messenger pages reconnect the reader in existing tabs without reloading. Only code packaged with the extension is executed.

Choose Zalo, Facebook or both during setup and change this in Settings. While unlocked with capture enabled, saved messages can appear beside recalled messages on the page. People using the device and page code may access content displayed there. Locking or pausing hides it. You can turn off avatar and attachment downloads in Settings. Text capture remains available while website access is granted.

Your controls

Pause capture at any time. Delete the archive in Settings; this also pauses capture. Removing the extension deletes extension data through Chrome's mechanisms. Signing out of Zalo does not delete saved copies. Copies are shared within the Chrome profile; use a separate profile on a shared device.

Password and encryption

A password to view your messages

StillHere uses a separate password to protect saved messages. Your unlock session lasts until you fully quit Chrome. Reloading the extension or detecting a sign-out or account change also ends the session; enter your password again to view messages.

Capture while locked

Once configured, enabled capture continues while locked using a public encryption key. Its private decryption key is protected by your password-derived key. Detected account changes stop locked capture until you unlock.

Pending encrypted copies are merged after unlocking and expire after the selected 7/30 days. The pending queue is limited to 3,000 batches and 140 MB of encoded ciphertext; new capture can fail when full.

Your password and legacy data

Legacy data is migrated to encryption using a password-derived key. The developer cannot recover a forgotten password. Existing copies from the same Chrome profile remain together in the password-protected vault.

Sharing and limited use

Message content is not sold, transmitted, shared or used for advertising, credit scoring or AI models. The developer does not receive or have access to your local archive. Data use is limited to saving and viewing messages, consistent with Chrome Web Store Limited Use requirements.

The connection status and displayed Zalo/Facebook account name are temporarily stored in chrome.storage.session. Facebook names are read only from its own-account menu. Zalo identity comes from displayed account information or the Zalo Web tab title.

If data from an earlier version is missing its decryption key, you can choose to keep a backup and continue saving new messages. The backup is encrypted with your new password and retained in local IndexedDB for later recovery until the extension is removed. This backup is separate from the active message list and its 7/30-day retention. A new password cannot recover messages whose old key is missing.

Language, filters and drafts

The VI/EN language and conversation/sender filters are remembered in chrome.storage.local. Search terms are not saved. Feedback content, topic and email are automatically saved as an AES-256-GCM encrypted local draft, valid for 30 days, and can be deleted separately in Feedback. The send-consent checkbox is never remembered. Drafts are never sent automatically.

Permissions

Content scripts on the selected Zalo Web, Facebook and Messenger sites read messages loaded in your conversation interface. The storage permission stores settings and encrypted data. The alarms permission cleans up expired data. CDN access is optional and Chrome asks when you enable avatar and media caching. Downloads are restricted to recorded image, GIF, sticker and video resources from supported Zalo or Facebook servers. The component library, font and QR image are bundled locally; no remote executable code is loaded.

On first setup, choose Zalo, Facebook or both. Website and file-server permissions are requested only for the selected platforms after you press Enable. Declining that request leaves capture off. Once granted, StillHere attaches to existing tabs without reloading the page. Switching off a platform stops capture; previous grants can be removed in Chrome extension settings. A suspended, discarded or closed tab cannot keep capturing.

Limitations and changes

Messages recalled before a copy was saved cannot be recovered. Unopened chats and messages recalled before capture are not guaranteed to be saved. Disappearing messages with a TTL and failed decryption states are skipped. Zalo interface changes may require adapter updates. New features and data processing will be disclosed before use; updates do not silently expand collection.

Exports, private notes and capture rules

Important marks and private notes are encrypted with messages on this device and never sent into conversations. Marking a message as important does not extend retention. Conversation capture rules are stored in local settings and apply to new capture and downloads; existing copies remain.

Encrypted JSON backups use a separate password you choose. Conversation JSON/HTML exports are unencrypted and anyone with the file can read them; a disclosure appears before download. Conversation exports contain text and message metadata. Encrypted backups also include files successfully downloaded by the extension; unavailable files cannot be recovered from a backup. Import merges validated records into the existing archive and encrypts them with your extension password. Downloaded files are outside automatic retention cleanup; you manage and delete them yourself.

The Connection page shows local tab status and download counts. It sends no reports or message content to a server. Searches, date filters and selected sender names are not transmitted externally.

Accounts and legacy data

New messages are separated by the account identity supplied by the page. The account name is encrypted with messages. Before an identity is available, the extension uses a temporary identifier for that page session. Legacy records without an account are not automatically assigned to a new account. The account filter is for browsing, not separate authentication: anyone with the extension password can view saved records within the same Chrome profile.
